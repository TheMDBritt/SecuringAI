## Exam facts

- **Exam:** SC-500, Implementing End-to-End Security Controls for Cloud and AI Workloads
- **Certification:** Microsoft Certified: Cloud and AI Security Engineer Associate
- **Replaces:** AZ-500
- **Four scored domains**, all weighted closely, so preparation has to be balanced rather than concentrated

## Domains (official weight ranges)

| # | Domain | Weight |
|---|---|---|
| 1 | Manage identity, access, and governance | **20-25%** |
| 2 | Secure storage, databases, and networking | **25-30%** |
| 3 | Secure compute | **20-25%** |
| 4 | Manage and monitor security posture | **20-25%** |

### Correction to the earlier transcription

An earlier version of this file listed five domains and treated "Securing AI Solutions and Governance" as a domain of its own. That is wrong. The published blueprint has four domains. AI workload security sits **inside Domain 3, Secure compute** (Purview DSPM for Copilot, Copilot Studio agent protection, Conditional Access for Entra Agent ID, Defender XDR blast-radius analysis), and governance sits **inside Domain 1**. Domain 2 is the heaviest at 25-30%.

### Content captured so far

- **Domain 1** Entra ID security: PIM, Conditional Access, MFA and passwordless, app registrations, OAuth consent, managed identities
- **Domain 2** storage, database and network protection, the heaviest-weighted domain
- **Domain 3** VM and server security (disk encryption, Bastion, JIT access, Azure Arc, Defender for Servers), application platform security, and the AI security subsection
- **Domain 4** Defender for Cloud posture management (CSPM, multicloud AWS and GCP connectors, Defender EASM) and Microsoft Sentinel
